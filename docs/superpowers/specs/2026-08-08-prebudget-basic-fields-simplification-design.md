# 성립전예산 기본정보 간소화 설계

## 1. 목적과 범위

성립전예산 입력 화면에서 실제 생성 기안문에 사용되지 않는 네 항목을 제거하고, 기존 `요구자`를 `사업담당자`로 변경하며 `품의권한부여자`를 별도 항목으로 추가한다.

이번 작업은 성립전예산 기능만 대상으로 한다. 예산 안건설명서와 결산설명서의 제안이유·근거 항목은 변경하지 않는다.

## 2. 기본정보 구성

### 유지 항목

- 학교명
- 회계연도
- 재원구분
- 문서 제목
- 부서명
- 관련 공문

### 변경·추가 항목

- 기존 `요구자`의 화면 명칭을 `사업담당자`로 변경한다.
- `품의권한부여자`를 별도 입력항목으로 추가한다.
- 초기 예시값은 사업담당자 `김담당`, 품의권한부여자는 공란으로 한다.

### 삭제 항목

- 교부기관
- 사업기간
- 편성 사유
- 관련 근거

삭제 항목은 입력 화면, 예시 데이터, 예시 적용, 자동점검과 신규 임시저장 데이터에서 제거한다.

## 3. 기안문 출력

기안문의 기본정보 부분을 다음 순서로 생성한다.

```text
가. 재원구분: 목적사업비(교육청)
나. 요구부서: 체육안전교육부
다. 사업담당자: 김담당
라. 품의권한부여자:
마. 예산요구 총액: 800,000원
```

화면 미리보기, 복사용 기안문, Word 및 PDF처럼 동일 문서 데이터를 사용하는 출력은 같은 명칭과 순서를 사용한다.

## 4. 데이터와 하위 호환성

- 기존 내부 `requester` 필드는 저장자료 호환을 위해 유지하되 화면과 문서에서는 `사업담당자`로 표시한다.
- 신규 내부 필드는 `approvalGranter: string`으로 정의한다.
- 새 초안의 `approvalGranter` 기본값은 빈 문자열이다.
- 기존 임시저장에 `approvalGranter`가 없으면 빈 문자열로 보완한다.
- 기존 임시저장에 교부기관·사업기간·편성 사유·관련 근거가 있어도 무시하고 나머지 자료를 정상 복원한다.
- 저장 키와 기존 예산항목 구조는 변경하지 않는다.

## 5. 예시와 자동점검

- 16개 예시에서 교부기관·사업기간·편성 사유·관련 근거 값을 제거한다.
- 예시 적용은 학교명, 회계연도, 사업담당자와 품의권한부여자를 현재 초안에서 유지한다.
- 예시의 확인 필요 항목은 `관련 공문`만 남긴다.
- 자동점검은 사업담당자가 비어 있으면 오류를 표시한다.
- 품의권한부여자는 선택 입력으로 취급하며 공란이어도 자동점검과 기안문 생성을 허용한다.
- 품의권한부여자가 공란이면 기안문의 `라. 품의권한부여자:` 줄은 유지하고 값만 비워 둔다.
- 예시 화면의 `실제 교부공문, 사업기간, 산출내역과 금액` 안내는 `실제 교부공문, 산출내역과 금액`으로 변경한다.

## 6. 검증과 완료 조건

1. 기본정보 화면에 삭제 대상 네 항목이 표시되지 않는다.
2. 사업담당자와 품의권한부여자가 각각 별도 입력란으로 표시된다.
3. 예시 적용 후 두 담당자 값은 덮어쓰지 않는다.
4. 기안문에 사업담당자와 품의권한부여자가 별도 줄로 표시되고, 품의권한부여자가 공란이어도 생성된다.
5. 기존 임시저장을 열어도 나머지 기본정보와 예산항목이 유지된다.
6. 예시 적용 후 관련 공문만 확인 필요로 표시된다.
7. 기존 16개 사업분류 매핑, 금액계산, 저장·복원 및 문서 생성 회귀테스트가 통과한다.
8. 전체 테스트와 빌드가 통과한 뒤 Preview에만 배포하며 Production은 변경하지 않는다.
