# 성립전예산 16개 예시 사업분류 매핑 수정 설계

## 1. 목적과 범위

현재 16개 예시가 모두 `교과 활동 → 교과활동지원`으로 생성되는 문제를 수정한다. 예시를 적용하면 각 사업의 성격에 맞는 `단위사업 → 세부사업 → 세부항목`이 함께 입력되어야 한다.

이번 작업은 사업분류 매핑만 대상으로 한다. 입력항목 삭제, 예시 선택 화면 개편, 기안문 수정 및 HWPX 다운로드는 포함하지 않는다.

## 2. 표시 원칙

- 초보자가 이해하기 쉽도록 `(목)`, `(구청)`, `(수)` 등의 재원 표기는 사업명에서 제거한다.
- 재원 성격은 기존의 목적사업비·구청보조금·수익자부담금 분류로 구분한다.
- 단위사업과 세부사업은 연결된 선택 항목으로 유지한다.
- 세부항목은 예시 적용 시 자동 입력되며 사용자가 수정할 수 있다.
- 실제 2024·2025 세입세출예산서에서 확인한 사업 계층과 현재 포털의 분류 체계를 함께 반영한다.

## 4. 데이터와 동작

예시 데이터의 각 항목에 단위사업, 세부사업, 세부항목을 개별 저장한다. 공통 생성 함수는 금액 등 공통 기본값만 만들며 사업분류를 고정하지 않는다.

예시를 적용할 때 세 값을 하나의 항목으로 함께 복사한다. 단위사업 변경으로 세부사업 선택지가 갱신된 뒤에도 예시에 지정된 세부사업 값이 유지되어야 한다. 기존 작성 내용이 있는 상태에서 예시를 적용하면 현재의 덮어쓰기 확인 절차를 그대로 사용한다.

현재 허용 목록에 없는 정상 조합인 `방과후 학교운영 → 돌봄교실운영`, `교육여건 개선 → 교육환경개선`은 연결 선택 목록에 추가한다. 기존의 `방과후 학교운영 → 늘봄학교 운영`, `학생 복지 → 학생 복지운영` 조합은 그대로 사용한다.

## 5. 오류 방지와 검증

- 16개 예시 모두 단위사업·세부사업·세부항목이 비어 있지 않아야 한다.
- 각 세부사업은 지정된 단위사업의 허용 목록에 포함되어야 한다.
- 예시 적용 결과가 예시 원본의 세 값과 정확히 일치해야 한다.
- 단위사업 선택지를 갱신하는 화면 동작 이후에도 세부사업이 초기화되지 않아야 한다.
- 사용자가 세부항목을 수정하면 수정값을 유지해야 한다.
- 시설개선, 늘봄, 돌봄, 졸업앨범, 현장체험학습 예시는 서로 다른 조합으로 적용되는 회귀 테스트를 둔다.
- 기존 직접 작성, 저장·복원, 금액 계산, 자동점검, 문서 생성 및 다운로드 기능의 회귀 테스트를 실행한다.

## 6. 완료 조건

1. 16개 예시가 공통 분류값을 사용하지 않는다.
2. 예시 선택 즉시 단위사업·세부사업·세부항목이 모두 표시된다.
3. 모든 단위사업·세부사업 조합이 선택 목록에서 유효하다.
4. 사용자가 자동 입력된 세 값을 수정할 수 있다.
5. 관련 단위 테스트, 전체 테스트 및 빌드가 통과한다.
6. 검증 후 Preview에만 배포하며, 사용자 승인 전에는 Production을 변경하지 않는다.
