# 예산지침 검색 결과 PDF 페이지 이동 수정 설계

## 목표

예산지침 검색 결과에서 `67쪽`처럼 특정 페이지를 선택하면 미리보기 제목만 바뀌는 것이 아니라, 사이트 내부 PDF 뷰어도 실제 선택한 페이지로 열리게 한다.

## 원인

현재 화면은 선택 페이지가 바뀔 때 iframe의 PDF 주소 중 `#page=N` 조각만 갱신한다. Chrome 기본 PDF 뷰어는 이미 로드된 iframe에서 주소 조각만 바뀌는 경우 이를 새로운 PDF 열기로 처리하지 않을 수 있다. 그 결과 React 상태와 제목은 `67쪽`으로 바뀌지만 PDF 뷰어는 기존 1쪽 화면에 머문다.

## 수정 방식

- 선택한 페이지 번호를 PDF iframe의 고유 식별값으로 사용한다.
- 검색 결과를 선택할 때 기존 iframe을 재사용하지 않고 해당 `#page=N` 주소를 가진 새 iframe을 생성한다.
- 새 iframe이 처음 로드될 때 브라우저 PDF 뷰어가 선택 페이지를 초기 페이지로 해석하게 한다.
- 기존 검색, 선택 표시, 미리보기 영역 스크롤, 전체 화면 보기, PDF 내려받기 기능은 유지한다.
- PDF.js 같은 별도 뷰어는 추가하지 않는다.

## 사용자 흐름

1. 사용자가 지침 본문을 검색한다.
2. 검색 결과에서 `67쪽`을 선택한다.
3. 선택 페이지 상태가 67로 변경된다.
4. 기존 PDF iframe이 제거되고 `#page=67` 주소의 iframe이 새로 생성된다.
5. 미리보기 제목과 PDF 뷰어의 실제 표시 페이지가 모두 67쪽으로 일치한다.

## 예외 및 호환성

- 브라우저가 PDF iframe 표시를 지원하지 않는 경우 기존 오류 안내와 `새 탭에서 해당 페이지 열기` 링크를 유지한다.
- 같은 페이지를 다시 선택할 때는 이미 해당 페이지가 표시 중이므로 불필요한 추가 동작을 요구하지 않는다.
- 다른 검색 결과 페이지를 연속 선택하면 매번 새 iframe으로 해당 페이지를 연다.

## 테스트 및 검증

- 먼저 실패 테스트를 추가해 서로 다른 검색 결과를 연속 선택했을 때 iframe이 선택 페이지별로 새로 생성되어야 함을 검증한다.
- 테스트가 기존 구현에서 실패하는 것을 확인한 뒤 최소 코드만 수정한다.
- 관련 컴포넌트 테스트, 전체 테스트, TypeScript/Vite 빌드를 실행한다.
- 실제 브라우저에서 검색 결과의 특정 페이지를 눌러 PDF 뷰어의 페이지 입력값과 화면이 선택 페이지로 열리는지 확인한다.
- 검증이 끝나면 `vercel deploy`로 Preview만 배포하며 `--prod`, `promote`, 운영 도메인 연결은 실행하지 않는다.

## 완료 기준

- 검색 결과에 표시된 페이지 번호와 PDF 뷰어의 실제 페이지가 일치한다.
- 기존 검색·다운로드·전체 화면 기능에 회귀가 없다.
- 전체 테스트와 빌드가 성공한다.
- Vercel Preview URL에서 동일 동작을 확인할 수 있다.
