# 본예산 업무 진행 흐름도 설계

## 목표

본예산 페이지를 처음 연 사용자가 전체 업무 순서와 현재 준비 상태를 한눈에 이해할 수 있도록, 제목 아래에 읽기 전용 5단계 업무 흐름도를 표시한다.

## 범위

- 본예산 페이지 제목과 기존 자료 구분 탭 사이에 흐름도를 배치한다.
- 흐름도는 진행 상태만 표시하며 초기 버전에서는 클릭·화면 이동 기능을 제공하지 않는다.
- 기존 세출자료 업로드·통합·검토, 세입자료 탭, 브라우저 저장 데이터와 다운로드 기능은 변경하지 않는다.
- 구현되지 않은 기능을 완료 상태나 계산 결과처럼 표시하지 않는다.

## 단계와 상태

흐름도는 다음 순서를 고정해서 보여준다.

```text
편성계획 수립 → 세출자료 통합·검토 → 세입자료·3% 검토 → 조정안 확정 → 안건설명서 작성
```

각 단계의 초기 상태는 다음과 같다.

1. 편성계획 수립: `준비 중`
2. 세출자료 통합·검토
   - 업로드 전: `자료 대기`
   - 업로드 후: 성공적으로 처리된 파일 수와 인식된 부서 수를 `파일 n개 · 부서 n개`로 표시
3. 세입자료·3% 검토: `자료 입력 대기`
4. 조정안 확정: `준비 중`
5. 안건설명서 작성: `준비 중`

세출 상태는 기존 `files`와 `rows`를 읽어 계산하며 해당 배열을 수정하지 않는다. 파일 수는 성공 상태인 파일만 세고, 부서 수는 공백을 제외한 고유 부서명 수로 계산한다.

## 화면 구성

- 각 단계는 번호, 단계명, 상태 문구를 포함한 카드로 표시한다.
- 단계 사이에는 업무 순서를 나타내는 화살표를 표시한다.
- PC 화면에서는 5단계를 한 줄로 배치한다.
- 좁은 화면에서는 카드를 한 열로 배치하고 화살표 방향을 세로 흐름에 맞게 표현한다.
- 기존 포털의 네이비·민트·스카이 색상과 본예산 화면의 글자 크기·테두리·간격을 따른다.
- 흐름도는 `aria-label`이 있는 별도 영역으로 제공해 보조기술에서도 업무 순서를 이해할 수 있게 한다.

## 컴포넌트 경계

- 새 `MainBudgetStatusFlow` 컴포넌트는 `rows`와 `files`를 읽기 전용 속성으로 받는다.
- 상태 계산은 별도 순수 함수로 분리해 화면 렌더링과 독립적으로 검증한다.
- `MainBudgetPage`는 제목 아래에서 컴포넌트를 렌더링하기만 하며 기존 탭 상태와 업로드 동작을 유지한다.

## 오류 및 빈 상태

- 자료가 없으면 오류로 표시하지 않고 `자료 대기`로 안내한다.
- 처리 실패·빈 파일은 성공 파일 수에 포함하지 않는다.
- 부서명이 없는 행은 부서 수에 포함하지 않는다.
- 이후 기능이 구현되기 전까지 세입·조정안·안건설명서는 고정 준비 상태를 유지한다.

## 검증 기준

- 본예산 페이지 제목 아래, 기존 탭 위에 5단계가 순서대로 표시된다.
- 세출자료 업로드 전에는 `자료 대기`가 표시된다.
- 성공 파일과 서로 다른 부서 자료가 있으면 실제 개수와 일치하는 상태가 표시된다.
- 실패·빈 파일과 빈 부서명은 집계에서 제외된다.
- 단계 카드는 클릭 가능한 요소가 아니다.
- 1440px에서는 가로 흐름, 390px에서는 페이지 가로 넘침 없는 세로 흐름으로 표시된다.
- 기존 본예산 집중 테스트와 전체 빌드가 통과한다.

## 제외 사항

- 편성계획 입력 화면과 일정 관리
- 단계별 클릭 이동
- 세입자료 입력 및 업무추진비 3% 계산
- 조정 시나리오 생성
- 진행 상태의 서버 저장 또는 사용자 간 공유
- Production 배포
