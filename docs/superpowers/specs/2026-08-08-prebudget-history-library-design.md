# 성립전예산 과거자료 보관함 설계

## 1. 목적

사용자가 연도별 최종 세입세출예산서 `.xlsx`를 업로드하면 문서 안의 `(성립전_○추)` 항목만 찾아 개인정보를 제외한 검색용 과거자료로 변환하고, 브라우저에 계속 보관한다. 사용자는 과거 사업을 검색·선택해 현재 성립전예산 입력화면으로 불러오고 올해 상황에 맞게 수정할 수 있다.

## 2. 확정된 원칙

- 서버 전송 없이 브라우저 안에서만 파일을 읽고 처리한다.
- 원본 Excel 파일은 브라우저에 저장하지 않는다.
- 담당자, 출력자, 결재자, 요구자, 연락처, 출력 일시는 추출하거나 저장하지 않는다.
- 학교명, 회계연도, 사업구조, 재원, 산출내역, 금액 등 공개 예산정보만 저장한다.
- 파일명이나 시트명보다 문서 내부 제목과 반복 표 머리글을 우선한다.
- 자동 연결이 불확실한 세입·세출 항목은 임의로 합치지 않고 `연결 확인 필요`로 표시한다.
- 과거자료는 참고값이며 올해 편성 확정값으로 표시하지 않는다.
- 기존 직접 편성, 임시저장, 자동점검, 문서 생성 기능은 유지한다.

## 3. 입력자료

### 3.1 우선 지원

- K-에듀파인에서 내려받은 연도별 최종 세입세출예산서 `.xlsx`
- 한 시트에 세입과 세출이 연속되고 페이지별 표 머리글이 반복되는 형식
- `예산액/전년도 예산액` 또는 `경정예산액/기정예산액` 형식

### 3.2 검증 기준본

- 서울옥정초등학교 2024학년도 최종 세입세출예산서
- 서울옥정초등학교 2025학년도 최종 세입세출예산서
- 기존 성립전예산 신청서 2종
- 서울 공립 초·중·고 9개 학교의 공식 공개 예산 합계·추경 차수

### 3.3 후속 지원 후보

- `.xls`
- 학교 홈페이지에서 내려받은 다른 출력 형식
- 개별 성립전예산 신청서 일괄 업로드

후속 형식은 표본 확보 후 별도 회귀테스트를 추가한다.

## 4. 추출 방식

### 4.1 문서 탐색

1. 실제 파일 형식이 OOXML인지 확인한다.
2. 숨김 시트를 포함한 모든 시트에서 문서 제목을 찾는다.
3. `세입예산명세서`, `세출예산명세서`, `정책`, `단위`, `세부`, `원가통계비목`, `산출기초` 머리글을 탐색한다.
4. 병합셀과 빈 셀 때문에 생긴 계층 누락은 위쪽의 가장 가까운 유효값을 상속한다.
5. `(성립전_1추)`부터 `(성립전_9추)`처럼 실제 표시된 차수를 정규식으로 추출한다.
6. `(목)`, `(구)`, `(수)`, `(국고)`, `(보조)` 등 재원 표시는 원문과 표준값을 함께 보관한다.

### 4.2 세입·세출 연결

다음 값을 이용해 연결 후보 점수를 계산한다.

- 회계연도
- 추경 차수
- 정규화된 사업명 또는 산출내역
- 금액
- 재원 표시
- 세부사업·세부항목 유사도

금액과 추경 차수가 일치하고 사업명 유사도가 충분한 경우만 자동 연결한다. 신뢰도가 기준보다 낮거나 한쪽에 후보가 여러 개인 경우 별도 항목으로 유지하고 `연결 확인 필요`를 표시한다. 화면에는 연결 근거와 신뢰도를 보여준다.

### 4.3 저장 데이터

각 과거자료는 다음 필드를 가진다.

- 내부 식별자
- 학교명
- 회계연도
- 추경 차수
- 재원 원문과 표준 재원구분
- 정책사업
- 단위사업
- 세부사업
- 세부항목
- 원가통계비목
- 산출내역
- 산출식 원문
- 단가·수량·횟수 추출값
- 세입금액
- 세출금액
- 대표금액
- 원본 시트명과 행 번호
- 연결상태와 신뢰도
- 확인 필요 사유
- 파일 지문과 등록일시

개인 이름, 결재정보, 연락처, 원본 파일 바이트는 저장하지 않는다.

## 5. 브라우저 저장소

### 5.1 IndexedDB

과거자료 보관함은 `IndexedDB`에 저장한다. 현재 작성 중인 초안은 기존 `localStorage`를 계속 사용하고 서로 분리한다.

저장소는 다음 객체 저장소로 나눈다.

- `imports`: 업로드 이력, 회계연도, 학교명, 파일 지문, 추출 건수, 등록일시
- `records`: 검색 가능한 성립전 사업 자료
- `settings`: 스키마 버전과 보관함 설정

### 5.2 중복 처리

- 파일 내용의 SHA-256 지문을 브라우저에서 계산한다.
- 동일 지문은 중복 등록하지 않는다.
- 같은 학교·연도지만 다른 파일이면 교체 또는 별도 등록을 사용자가 선택한다.
- 교체 전 기존 자료 건수와 새 자료 건수를 비교해 보여준다.

### 5.3 삭제와 백업

- 연도별 삭제, 파일별 삭제, 전체 초기화를 제공한다.
- 삭제와 초기화에는 확인창을 표시한다.
- 개인정보가 제외된 보관함을 JSON으로 백업·복원할 수 있게 한다.
- 백업에는 원본 Excel을 포함하지 않는다.

## 6. 화면 구성

성립전예산 화면 상단에 `과거자료 보관함` 영역을 추가한다.

### 6.1 등록

- `최종예산서 등록` 버튼
- 여러 파일 동시 선택과 드래그앤드롭
- 파일별 진행상태
- 인식한 학교명·연도·추경 차수
- 추출 건수, 자동 연결 건수, 확인 필요 건수
- 잘못된 파일에 대한 이해하기 쉬운 오류 안내

### 6.2 검색 목록

- 연도, 학교명, 추경 차수, 재원, 세부사업, 원가통계비목 필터
- 사업명·산출내역 통합검색
- 자동 연결/확인 필요 상태 필터
- 대표금액 표시
- 현재 조회 건수
- 기본 정렬은 최신 연도, 최근 추경 차수, 사업명 순

### 6.3 상세 확인

- 세입 원문과 세출 원문을 나란히 표시
- 연결 근거와 신뢰도
- 추출된 계층·비목·산출식·금액
- 불확실한 항목 강조
- `올해 자료로 불러오기` 버튼

### 6.4 올해 자료로 불러오기

- 회계연도를 현재 연도로 변경한다.
- 학교명은 현재 로그인 학교 또는 현재 입력값을 유지한다.
- 과거 사업명, 재원, 사업 계층, 비목, 산출내역, 단가·수량·횟수를 복사한다.
- 공문번호, 교부기관, 사업기간, 편성 사유처럼 최종예산서에 없는 값은 빈칸 또는 `확인 필요`로 둔다.
- 기존 작성 내용이 있으면 덮어쓰기 전에 확인한다.
- 과거금액과 올해 수정금액의 증감액·증감률을 실시간 계산한다.

## 7. 오류 처리

- Excel이 아니거나 손상된 파일: 실제 형식을 확인하라는 오류
- 제목을 찾지 못함: 지원 대상 최종 세입세출예산서인지 확인 안내
- 성립전 표시 없음: 정상 파일이지만 추출 항목이 없음을 안내
- 일부 표만 인식: 추출 가능 항목은 저장하되 누락 가능성과 행 위치 표시
- 금액 불일치: 세입·세출을 합치지 않고 확인 필요 표시
- 저장공간 부족: 기존 자료 삭제 또는 백업 후 초기화 안내
- IndexedDB 사용 불가: 현재 세션에서만 분석 가능하다고 안내하고 영구저장을 비활성화

## 8. 성능과 개인정보

- 파일 읽기와 대량 파싱은 Web Worker 사용을 우선 검토한다.
- 행 단위 처리 진행률을 표시해 화면 정지처럼 보이지 않게 한다.
- 저장 전 허용된 필드만 새 객체로 만들어 개인정보가 섞이지 않게 한다.
- 원본 셀 전체나 행 전체는 저장하지 않는다.
- 개인정보로 보이는 이름·전화번호·전자우편·결재정보는 저장 전 한 번 더 제거한다.
- 외부 API, 분석 서버, Supabase Storage로 파일을 전송하지 않는다.

## 9. 테스트 전략

### 9.1 파서 단위테스트

- 2024·2025 최종예산서의 연도와 추경 차수 인식
- 반복 머리글과 병합셀 사이에서 계층 상속
- 모든 `(성립전_○추)` 행 탐색
- 재원 표시 정규화
- 원 단위 산출기초와 천원 단위 예산액 구분
- 세입·세출 연결 성공·실패·다중 후보
- 개인정보 필드가 결과에 포함되지 않음

### 9.2 저장소 테스트

- IndexedDB 등록·검색·교체·삭제
- 동일 파일 중복 방지
- 브라우저 재접속 후 자료 유지
- 스키마 버전 변경 시 마이그레이션
- JSON 백업·복원

### 9.3 화면 테스트

- 여러 파일 업로드
- 필터·검색·정렬
- 확인 필요 표시
- 기존 작성 내용 덮어쓰기 확인창
- 선택 자료를 현재 입력화면에 반영
- 증감액·증감률 계산
- 초기화 확인창

### 9.4 회귀테스트

- 기존 성립전예산 직접 입력
- 임시저장과 자동복원
- 자동점검과 기안문 생성
- 기존 Word·PDF·Excel 다운로드
- 예산 안건설명서와 결산설명서 기능

## 10. 구현 순서

1. 개인정보가 제거된 과거자료 도메인 모델과 최종예산서 파서
2. 2024·2025 실제 파일 기반 파서 테스트
3. 세입·세출 연결 및 신뢰도 규칙
4. IndexedDB 저장소와 중복 감지
5. 과거자료 등록·검색·상세 화면
6. 올해 자료 불러오기와 증감 비교
7. 백업·복원·삭제
8. 전체 회귀테스트와 대용량 성능 확인
9. Vercel Preview 배포 및 사용자 실파일 검증

## 11. 배포 원칙

- 기능별 테스트와 전체 회귀테스트가 통과한 뒤 Preview에만 배포한다.
- 사용자가 실제 최종예산서로 확인하기 전에는 완료로 표시하지 않는다.
- 사용자 최종 승인 전에는 Production 배포, Promote, 운영 도메인 변경을 하지 않는다.
