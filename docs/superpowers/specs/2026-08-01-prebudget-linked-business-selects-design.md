# 성립전예산 단위사업·세부사업 연동 콤보박스 설계

## 목표

성립전예산의 각 예산항목에서 단위사업을 표준 목록으로 선택하고, 선택한 단위사업에 속한 세부사업만 두 번째 콤보박스에서 선택할 수 있게 한다. 세부항목은 기존처럼 사용자가 직접 입력한다.

## 확정 화면 구조

기존 예산항목의 `세부사업명` 직접 입력칸을 다음 두 입력으로 교체한다.

1. `단위사업` 콤보박스
2. `세부사업` 연동 콤보박스

기존 `세부항목`, `원가통계비목`, `산출내역`, `단가`, `수량`, `횟수` 입력은 유지한다.

새 예산항목을 추가하면 단위사업과 세부사업은 모두 `선택하세요` 상태로 시작한다. 단위사업을 선택하기 전에는 세부사업 콤보박스를 비활성화한다. 단위사업을 변경하면 이전 단위사업의 세부사업 값은 즉시 초기화하여 잘못된 조합이 남지 않게 한다.

## 데이터 구조

단위사업별 세부사업 목록은 성립전예산 도메인 모듈에 읽기 전용 연결표로 둔다. 예산항목 데이터에는 다음 값을 각각 저장한다.

- `unitBusiness`: 선택한 단위사업명
- `business`: 선택한 세부사업명
- `detail`: 사용자가 직접 입력한 세부항목

기존 `business` 필드는 세부사업명 저장에 계속 사용하여 현재 데이터 흐름과의 변경 범위를 줄인다. 새 `unitBusiness` 필드만 추가한다.

## 동작 흐름

1. 사용자가 단위사업을 선택한다.
2. 해당 단위사업의 세부사업 목록을 조회한다.
3. 세부사업 콤보박스를 활성화하고 연결된 항목만 표시한다.
4. 사용자가 세부사업을 선택한다.
5. 단위사업을 다른 값으로 변경하면 세부사업을 빈 값으로 초기화한다.
6. 사용자가 세부항목과 나머지 예산정보를 입력한다.
7. 항목 추가·삭제와 요구금액 합계 계산은 현재와 동일하게 동작한다.

## 예외 처리

- 단위사업 미선택 시 세부사업 선택을 막고 `단위사업을 먼저 선택하세요` 안내를 표시한다.
- 선택된 단위사업에 없는 세부사업 값은 유효한 조합으로 인정하지 않는다.
- 단위사업을 바꾸면 이전 세부사업을 자동 삭제해 잘못된 조합을 방지한다.
- 목록에 없는 단위사업과 세부사업의 직접 입력 기능은 이번 범위에 포함하지 않는다.

## 테스트 및 검증

- 표준 연결표가 20개 단위사업을 모두 포함하는지 검증한다.
- 대표적인 다중 세부사업 항목인 `교과 활동`과 단일 세부사업 항목인 `급식 관리`의 연결 결과를 검증한다.
- 새 예산항목에서 세부사업 콤보박스가 비활성화되는지 검증한다.
- 단위사업을 선택하면 해당 세부사업만 표시되는지 검증한다.
- 단위사업 변경 시 기존 세부사업 값이 초기화되는지 검증한다.
- 기존 금액 계산, 항목 추가·삭제 및 전체 애플리케이션 테스트가 계속 통과하는지 확인한다.
- TypeScript와 Vite production build를 확인한다.

## 배포 원칙

수정과 검증 후 `vercel deploy`로 Preview만 배포한다. 사용자가 Preview에서 연동 콤보박스를 확인하고 별도로 운영 배포를 승인하기 전에는 `--prod`, `promote`, 운영 도메인 연결을 실행하지 않는다.

## 완료 기준

- 각 예산항목에서 단위사업과 세부사업을 표준 목록으로 선택할 수 있다.
- 세부사업 목록은 선택한 단위사업에 맞게 제한된다.
- 단위사업 변경 시 잘못된 세부사업 값이 남지 않는다.
- 세부항목은 직접 입력할 수 있다.
- 전체 테스트와 빌드가 통과한다.
- Vercel Preview에서 사용자 확인이 가능하다.
