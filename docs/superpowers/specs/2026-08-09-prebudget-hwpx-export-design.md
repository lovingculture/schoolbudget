# 성립전예산 기안문 HWPX 생성 설계

## 목표

성립전예산 기안문을 현재 화면 미리보기 문안을 기준으로 실제 한글 프로그램에서 열고 수정할 수 있는 `.hwpx` 파일로 생성한다. 미리보기, 전체 복사, HWPX, Word, PDF는 같은 문안과 항목 순서를 사용한다.

## 범위

- 성립전예산 기안문 다운로드 영역에 `한글(HWPX)` 버튼을 추가한다.
- 브라우저에서 표준 HWPX ZIP 패키지를 생성한다.
- 제목, 관련 공문, 편성 문장, 기본정보, 요구내역과 금액을 문서에 반영한다.
- 실제 성립전예산 기안문 원본이 제공되기 전까지 현재 미리보기를 기준으로 단정한 표준 서식을 사용한다.
- 실제 원본이 제공되면 데이터 생성 규칙은 유지하고 여백·글꼴·문단 간격 등 서식 계층만 교체할 수 있게 분리한다.
- 가짜 `.hwp` 파일이나 확장자만 변경한 파일은 만들지 않는다.

## 공통 문안 생성 규칙

`createPrebudgetDocument`가 화면과 모든 다운로드 형식에서 사용하는 단일 문안 데이터를 만든다. 각 출력기가 별도로 항목명이나 순번을 재구성하지 않는다.

### 품의권한 부여자가 입력된 경우

```text
가. 재원구분
나. 요구부서
다. 사업담당자
라. 품의권한 부여자
마. 예산요구 총액
바. 성립전예산 요구내역
```

### 품의권한 부여자가 공란인 경우

품의권한 부여자 줄은 빈 줄로 남기지 않고 완전히 제외한다. 뒤 항목 순번도 자동으로 당긴다.

```text
가. 재원구분
나. 요구부서
다. 사업담당자
라. 예산요구 총액
마. 성립전예산 요구내역
```

이 조건은 미리보기, 전체 복사, HWPX, Word, PDF에 동일하게 적용한다.

## HWPX 문서 구조

HWPX는 다음 필수 구성요소를 포함하는 ZIP 패키지로 생성한다.

- `mimetype`
- `version.xml`
- `Contents/content.hpf`
- `Contents/header.xml`
- `Contents/section0.xml`
- `META-INF/container.xml`
- 필수 메타데이터 파일

`section0.xml`에는 다음 순서로 내용을 배치한다.

1. 가운데 정렬한 문서 제목
2. 관련 공문
3. 해당 학년도와 사업명을 포함한 편성 문장
4. 동적으로 순번이 정해지는 기본정보
5. 성립전예산 요구내역

요구내역은 단위사업, 세부사업, 세부항목, 원가통계비목, 산출기초, 금액을 포함한다. 금액에는 천 단위 쉼표와 `원`을 적용한다. 항목이 많으면 한글의 일반 문단 흐름에 따라 다음 페이지로 이어지도록 고정 높이나 강제 잘라내기를 사용하지 않는다.

## 화면과 다운로드

다운로드 버튼은 다음 순서로 표시한다.

1. 한글(HWPX)
2. Word
3. PDF

전체 복사 기능은 유지한다. Excel 다운로드는 제공하지 않는다. HWPX 생성 중에는 버튼을 비활성화하고 완료 후 복구한다. 생성 실패 시 사용자가 이해할 수 있는 오류 안내를 표시한다.

## 오류 처리

- 문서 생성 전에 기존 자동점검을 통과해야 한다.
- HWPX ZIP 생성 또는 Blob 변환에 실패하면 다운로드를 시작하지 않는다.
- 오류 메시지는 `한글(HWPX) 파일을 만들지 못했습니다. 다시 시도해 주세요.`로 안내한다.
- 품의권한 부여자 공란은 오류가 아니며 문서 생성이 정상 진행된다.

## 검증

- 품의권한 부여자가 있을 때 `가`부터 `바`까지 생성되는지 확인한다.
- 공란일 때 해당 줄이 제거되고 `라`, `마`로 재번호화되는지 확인한다.
- 미리보기, 복사 문안, Word, PDF, HWPX의 내용과 순서가 일치하는지 확인한다.
- 생성된 HWPX를 다시 열어 필수 ZIP 항목과 XML 유효성을 검사한다.
- HWPX 내부에 제목, 관련 공문, 담당자, 총액, 요구내역이 들어 있는지 검사한다.
- 한글 프로그램에서 열 수 있는 표준 HWPX 구조인지 확인한다.
- 기존 16개 예시, 임시저장, Word, PDF 및 다른 포털 기능의 회귀테스트를 실행한다.

## 배포 제한

구현과 검증 후에도 Production에는 배포하지 않는다. GitHub 푸시와 Preview 재배포는 사용자의 별도 승인을 받은 뒤 진행한다.
