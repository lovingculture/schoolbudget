# 성립전예산 내장 예시문서 라이브러리 설계

## 1. 목적

사용자가 과거 파일을 업로드하거나 보관하지 않아도 성립전예산 작성 방법을 바로 이해하고 활용할 수 있도록 포털 안에 대표 예시문서를 제공한다. 예시는 사용자가 제공한 2024·2025 최종 세입세출예산서와 성립전예산 신청서, 서울특별시교육청 공개 예산자료를 분석해 만든다. 실제 학교나 개인을 식별할 수 있는 정보는 제거하고 학교급·재원·사업유형별 공통 구조만 일반화한다.

## 2. 범위

### 2.1 포함

- 개인정보가 제거된 내장 예시문서 약 12종
- 학교급, 재원, 사업유형, 원가통계비목 필터
- 키워드 검색
- 예시 상세보기와 기안문 미리보기
- `이 예시로 작성하기`를 통한 현재 입력화면 자동 채우기
- 복사 후 반드시 수정해야 하는 항목 표시
- 기존 자동점검과 문서 생성 연계

### 2.2 제외

- 사용자의 과거 최종예산서 업로드
- 과거자료 자동 추출·검색
- 원본 Excel 또는 추출자료의 IndexedDB 저장
- 파일 중복 감지
- 과거자료 백업·복원
- 외부 서울교육청 사이트 실시간 조회
- 실제 학교 자료를 그대로 보여주는 기능

## 3. 예시자료 작성 원칙

- 실제 공개 예산의 사업구조와 산출방식을 참고하되 특정 학교 문서를 복제하지 않는다.
- 학교명은 `서울○○초등학교`, `서울○○중학교`, `서울○○고등학교`처럼 익명화한다.
- 교부기관은 필요한 경우 `○○교육지원청`, `○○구청`처럼 일반화한다.
- 담당자·요구자·결재자 이름은 포함하지 않는다.
- 공문번호는 `교육지원과-0000(20XX. X. X.)` 같은 수정용 예시로 표시한다.
- 금액은 실제 자료에서 확인한 현실적인 범위를 사용하되 특정 학교 금액을 그대로 재현하지 않는다.
- 예시는 확정안이 아니라 사용자가 교부 공문과 학교 상황에 맞게 수정해야 하는 참고자료임을 명시한다.
- 예시 데이터는 정적 TypeScript 또는 JSON 데이터로 포털 번들 안에 포함하고 외부 서버에서 불러오지 않는다.

## 4. 초기 예시문서 구성

초기 버전은 다음 12종을 제공한다.

1. 초등학교 독서·도서구입 지원
2. 초등학교 교육과정 운영 지원
3. 초등학교 학생안전 인력 지원
4. 초등학교 시설·환경개선 보조금
5. 중학교 방학 프로그램 수익자부담금
6. 중학교 진로·체험활동 지원
7. 중학교 학생복지 지원
8. 중학교 강사비·운영수당 편성
9. 고등학교 학교운동부 지원
10. 고등학교 국고보조 교육사업
11. 목적사업업무추진비 포함 사업
12. 여러 원가통계비목으로 나뉘는 복합 사업

표본은 목적사업비, 자치단체 보조금, 수익자부담금, 국고보조금과 주요 학교급을 모두 포함한다. 각 예시는 한 개 이상의 예산항목을 가질 수 있으며 복합 사업 예시는 여러 비목을 현재 입력화면에 함께 복사한다.

## 5. 예시문서 데이터 모델

각 예시는 다음 값을 가진다.

- 예시 ID
- 제목
- 학교급: 초등학교, 중학교, 고등학교, 공통
- 재원구분
- 사업유형 태그
- 예시 설명
- 학교명 예시
- 회계연도 예시
- 문서 제목
- 교부기관 예시
- 관련 공문 예시
- 사업기간 예시
- 편성 사유
- 관련 근거 예시
- 단위사업
- 세부사업
- 세부항목
- 원가통계비목
- 산출내역
- 단가·수량·횟수
- 편성금액
- 기안문 미리보기용 문구
- 자동점검 참고사항
- 반드시 수정해야 하는 필드 목록
- 자료 출처 분류와 검토일자

자료 출처에는 개인 이름이나 원본 파일의 전체 행을 저장하지 않는다. `사용자 제공 익명화 표본`, `서울교육청 공개예산 분석`처럼 출처 유형만 표시한다.

## 6. 화면 설계

### 6.1 진입

성립전예산 화면 상단에 두 가지 시작 방법을 제공한다.

- `직접 작성하기`
- `예시문서에서 시작하기`

기존 직접 작성 화면은 기본 경로로 유지한다. 예시문서 선택은 선택 기능이며 기존 사용 흐름을 막지 않는다.

### 6.2 예시 목록

목록에는 카드 또는 표 형태로 다음 값을 표시한다.

- 예시 제목
- 학교급
- 재원구분
- 사업유형
- 대표 원가통계비목
- 예시 편성금액
- 항목 수

다음 검색과 필터를 제공한다.

- 초등학교·중학교·고등학교·공통
- 목적사업비·자치단체 보조금·수익자부담금·국고보조금
- 사업유형
- 원가통계비목
- 제목·사업명·산출내역 키워드 통합검색
- 필터 초기화
- 현재 조회 건수

### 6.3 상세보기

예시를 선택하면 다음 내용을 보여준다.

- 적용 상황과 사용 목적
- 기본정보 예시
- 예산항목 표
- 산출식과 총액
- 편성 사유와 관련 근거
- 기안문 미리보기
- 자동점검 결과 예시
- 사용 전 수정할 항목
- `이 예시로 작성하기` 버튼

화면 상단에는 다음 안내를 고정 표시한다.

> 실제 공개 예산자료를 참고한 작성 예시입니다. 학교 상황, 교부 공문, 사업기간과 실제 금액에 맞게 반드시 수정해 주세요.

### 6.4 이 예시로 작성하기

버튼을 누르면 예시를 현재 성립전예산 초안으로 복사한다.

- 학교명은 현재 포털의 학교명을 유지한다.
- 회계연도는 현재 입력값 또는 현재 학년도를 유지한다.
- 예시의 사업구조, 비목, 산출내역, 단가·수량·횟수를 복사한다.
- 교부기관, 공문번호, 사업기간, 실제 금액처럼 확인이 필요한 값은 복사하되 `확인 필요` 상태로 표시한다.
- 기존 작성 내용이 있으면 덮어쓰기 전에 확인창을 표시한다.
- 복사 후 바로 편집 화면으로 이동한다.
- 예시 데이터는 편집 가능한 일반 초안으로 변환하고 예시 원본은 변경하지 않는다.

## 7. 현재 입력모델 보완

현재 성립전예산 입력모델에 없는 다음 값은 예시 기능과 함께 단계적으로 추가한다.

- 학교급
- 교부기관
- 사업기간
- 편성 사유
- 관련 근거
- 예시 출처 ID
- 확인 필요 필드 목록

기존 저장 초안과의 하위 호환성을 유지한다. 예전 초안에 새 필드가 없으면 빈값으로 보완하고 기존 항목과 금액은 그대로 복원한다.

## 8. 개인정보와 출처 관리

- 실제 담당자·출력자·결재자·요구자 이름을 코드나 예시에 포함하지 않는다.
- 전화번호, 전자우편, 사용자 계정, 출력일시를 포함하지 않는다.
- 실제 학교명은 연구·검증 메모에서만 사용하고 화면 예시에는 익명 학교명을 사용한다.
- 공개자료에서 가져온 문구를 장문으로 복제하지 않고 사업구조와 계산방식만 일반화한다.
- 예시별 출처 유형과 검토연도만 기록해 자료의 성격을 설명한다.
- 포털 실행 중 외부 사이트나 외부 API를 호출하지 않는다.

## 9. 오류와 사용자 보호

- 예시 복사 전 기존 입력내용 덮어쓰기 확인
- 실제 공문번호·금액·기간이 예시값 그대로 남아 있으면 자동점검에서 경고
- `○○`, `0000`, `20XX` 같은 예시 표시가 남아 있으면 문서 생성 전 확인 필요 처리
- 단가×수량×횟수와 편성금액 불일치 경고
- 재원구분과 원가통계비목이 예시 목적과 맞지 않을 때 주의 표시
- 초기화 버튼에 확인창 표시
- 예시 선택 중 오류가 발생해도 현재 작성 중인 초안은 유지

## 10. 테스트 전략

### 10.1 예시 데이터 테스트

- 12개 예시 ID가 중복되지 않음
- 학교급·재원구분·사업유형이 모두 존재함
- 모든 예시가 하나 이상의 유효 예산항목을 가짐
- 단가×수량×횟수와 편성금액이 일치함
- 개인 이름·전화번호·전자우편이 포함되지 않음
- 익명화 표시와 필수 수정 필드가 존재함

### 10.2 검색·필터 테스트

- 학교급 필터
- 재원구분 필터
- 사업유형 필터
- 원가통계비목 필터
- 키워드 검색
- 필터 초기화와 조회 건수

### 10.3 불러오기 테스트

- 현재 학교명과 회계연도 유지
- 여러 예산항목 복사
- 기존 입력 덮어쓰기 확인
- 필수 수정 필드 강조
- 예시 원본 불변
- 복사 후 자동점검과 기안문 생성 연결

### 10.4 회귀테스트

- 기존 직접 입력
- 단위사업·세부사업 연동
- 원가통계비목 설명
- 금액 자동 계산
- 임시저장과 자동복원
- 자동점검과 문서 생성
- 기존 다운로드 기능
- 예산·결산 안건설명서 기능

## 11. 구현 순서

1. 예시문서 데이터 모델과 익명화된 12개 표본 작성
2. 예시 데이터 유효성·개인정보 검사 테스트
3. 예시 목록과 검색·필터 화면
4. 예시 상세보기와 기안문 미리보기
5. `이 예시로 작성하기`와 기존 입력모델 보완
6. 필수 수정값 자동점검
7. 기존 초안 하위 호환성과 전체 회귀테스트
8. Vercel Preview 배포와 사용자 검토

## 12. 배포 원칙

- 예시 화면은 실제 데이터로 작동해야 하며 자리표시자만 있는 시제품으로 끝내지 않는다.
- 기능별 테스트와 전체 회귀테스트가 통과한 뒤 Preview에만 배포한다.
- 사용자가 예시 내용과 입력화면 반영 결과를 확인하기 전에는 완료로 표시하지 않는다.
- 사용자 최종 승인 전에는 Production 배포, Promote, 운영 도메인 변경을 하지 않는다.
