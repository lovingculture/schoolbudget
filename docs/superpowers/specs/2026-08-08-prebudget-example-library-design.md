# 초보자용 성립전예산 예시 라이브러리 설계

## 1. 목표

예산 업무를 처음 맡은 사용자도 어려운 회계 용어를 먼저 알 필요 없이 질문에 답하면서 적절한 성립전예산 예시를 찾고, 해당 예시를 현재 작성 화면으로 불러와 수정할 수 있게 한다.

초기버전은 재원 성격에 따라 3개 분류와 16개 세부 예시를 제공한다. 사용자의 과거 파일을 업로드하거나 저장하는 기능은 포함하지 않는다.

## 2. 핵심 사용자 흐름

### 2.1 1단계: 돈의 출처 선택

첫 화면에서 전문용어 대신 다음 질문을 표시한다.

> 이 사업비는 어디에서 받았나요?

- `교육청·교육지원청에서 특정 사업을 위해 받았어요` → 목적사업비
- `구청이나 지방자치단체에서 지원받았어요` → 구청보조금
- `학부모가 비용의 전부 또는 일부를 부담해요` → 수익자부담금
- `잘 모르겠어요` → 확인 방법 안내

`잘 모르겠어요`를 선택하면 교부공문의 발신기관·제목, 보조금 교부결정서, 가정통신문과 징수계획에서 재원을 확인하는 방법을 보여준다. 사용자를 대신해 재원을 임의로 확정하지 않는다.

### 2.2 2단계: 사업 목적 선택

재원을 선택하면 해당 분류의 세부 예시만 카드로 보여준다. 카드에는 쉬운 제목, 한 문장 설명, 주요 편성항목과 `자세히 보기`를 표시한다.

### 2.3 3단계: 예시 검토

상세 화면에는 다음 내용을 표시한다.

- 이 예시를 사용하는 상황
- 준비해야 하는 정보
- 교부기관·사업기간·관련 근거 예시
- 단위사업·세부사업·원가통계비목
- 산출내역, 단가·수량·횟수와 편성금액
- 자동점검 예시
- 기안문 간단 미리보기
- 사용자가 반드시 수정하거나 확인할 항목

### 2.4 4단계: 작성 화면으로 복사

`이 예시로 작성하기`를 누르면 현재 학교명과 회계연도는 유지하고 선택한 예시의 사업정보와 예산항목을 편집 가능한 초안으로 깊은 복사한다.

기존 작성 내용이 있으면 다음 확인창을 표시한다.

> 현재 작성 중인 내용이 예시 내용으로 바뀝니다. 계속하시겠습니까?

취소하면 현재 초안과 선택 화면을 변경하지 않는다. 승인하면 작성 화면으로 이동하고 `확인 필요` 항목을 화면 상단에 강조한다.

## 3. 초기 예시 16종

### 3.1 목적사업비 10종

1. 기초학력 지원
2. 맞춤형 늘봄교실
3. 초등돌봄교실
4. 방과후학교 운영 지원
5. 디지털·AI 교육 지원
6. 학생 맞춤통합지원
7. 교육복지 지원
8. 학생안전 인력 운영
9. 독서교육·도서구입
10. 진로·체험활동 지원

### 3.2 구청보조금 3종

1. 시설·환경개선 지원
2. 교육과정·체험활동 지원
3. 학생복지 지원

### 3.3 수익자부담금 3종

1. 졸업앨범비
2. 현장체험학습비
3. 방과후학교 수강료

예시의 사업명과 금액은 참고값이며 실제 교부공문, 보조금 교부결정서, 징수계획 및 학교 상황에 맞게 수정해야 한다.

## 4. 찾기와 탐색 방식

기본 탐색은 3개 재원 카드에서 시작하는 안내형 방식이다. 사용자가 사업명을 알고 있을 때는 통합검색을 함께 제공한다.

검색 대상은 다음과 같다.

- 쉬운 예시 제목
- 재원구분
- 사업 목적과 설명
- 단위사업·세부사업
- 원가통계비목
- 산출내역
- 동의어: `돌봄`, `늘봄`, `도서`, `책`, `학부모 부담`, `구청 지원` 등

현재 선택된 재원 안에서 검색하는 것이 기본이며 `전체 예시에서 검색`을 선택하면 16종 전체를 검색한다. 검색 결과 수와 초기화 버튼을 제공한다.

## 5. 데이터 구조

각 예시는 정적 TypeScript 데이터로 앱에 포함하며 외부 API를 호출하지 않는다.

각 예시는 다음 값을 가진다.

- 예시 ID
- 재원구분: 목적사업비, 구청보조금, 수익자부담금
- 쉬운 제목과 검색 동의어
- 사용 상황과 준비정보
- 문서 제목
- 교부기관 예시
- 관련 공문 예시
- 사업기간 예시
- 편성 사유와 관련 근거
- 단위사업·세부사업·세부항목
- 원가통계비목과 산출내역
- 단가·수량·횟수·편성금액
- 기안문 미리보기
- 자동점검 참고사항
- 확인 필요 필드 목록
- 출처 분류와 검토일

예시를 추가할 때 데이터 한 건만 추가하면 목록, 검색, 상세 화면에 자동 반영되도록 구성한다.

## 6. 현재 초안 모델과 저장 호환성

현재 초안에는 다음 값을 추가한다.

- 교부기관
- 사업기간
- 편성 사유
- 관련 근거
- 예시 출처 ID
- 확인 필요 필드 목록

학교급 필드는 초기 예시 선택에 사용하지 않는다. 이미 추가된 학교급 값이 저장자료에 있으면 보존하되 화면 선택의 필수조건으로 만들지 않는다.

기존 localStorage 키를 유지한다. 이전 초안에 새 필드가 없으면 빈 값으로 보완한다. 회계연도가 문자열 숫자로 저장되어 있으면 유한한 숫자로 변환하고 변환할 수 없으면 현재 기본 회계연도를 사용한다. 재원구분은 허용된 세 값만 복원하고 그 밖의 값은 기본 재원으로 되돌린다.

## 7. 초보자 안내 문구

예시 화면 상단에 다음 안내를 고정 표시한다.

> 이 자료는 성립전예산 작성을 돕기 위한 예시입니다. 실제 교부공문, 사업기간, 산출내역과 금액을 확인하여 학교 상황에 맞게 수정해 주세요.

각 상세 화면에는 다음 세 구역을 구분한다.

- `이런 경우에 사용해요`
- `작성 전에 준비하세요`
- `복사한 뒤 꼭 확인하세요`

전문용어에는 짧은 설명을 함께 제공하고, 자동분석 결과는 확정값이 아니라 참고 또는 확인 필요로 표시한다.

## 8. 검증과 개인정보 보호

- 실제 학교명, 담당자명, 요구자명, 전화번호, 이메일, 계정, 출력일시는 예시에 포함하지 않는다.
- 학교명과 기관명은 `서울○○초등학교`, `○○교육지원청`, `○○구청`처럼 익명화한다.
- 공문번호와 연도는 `교육지원과-0000(20XX. X. X.)`처럼 예시임을 드러낸다.
- `○○`, `0000`, `20XX`가 포함된 필드는 복사 후 `확인 필요`로 표시한다.
- 단가 × 수량 × 횟수와 편성금액이 일치하지 않으면 예시 데이터 테스트가 실패한다.
- 16개 ID 중복, 필수값 누락, 분류별 개수 불일치, 개인정보 패턴을 자동검사한다.

## 9. 오류 처리와 사용자 보호

- 검색 결과가 없으면 검색어와 분류를 바꾸도록 안내하고 초기화 버튼을 제공한다.
- 예시 적용 중 오류가 나도 현재 작성 중인 초안은 유지한다.
- 예시 원본은 읽기 전용으로 유지하고 사용자가 수정하는 초안과 객체를 공유하지 않는다.
- 사용자가 확인 필요 필드를 실제 값으로 바꾸면 해당 경고만 제거한다.
- 예시 문구가 남아 있으면 문서 생성 전에 다시 경고하되 사용자의 작업을 임의로 삭제하지 않는다.
- 초기화 버튼에는 기존 확인창을 유지한다.

## 10. 테스트와 완료 기준

### 데이터 테스트

- 전체 16종과 분류별 `10·3·3` 개수
- ID 중복 없음
- 모든 예시에 하나 이상의 예산항목 존재
- 금액 계산 일치
- 실제 개인정보 패턴 없음
- 예시 표시는 확인 필요 필드에 등록됨

### 탐색 테스트

- 재원 질문에서 3개 분류 선택
- `잘 모르겠어요` 안내
- 선택한 분류의 예시만 표시
- 쉬운 검색어와 동의어 검색
- 전체 예시 검색
- 검색 결과 수와 초기화

### 불러오기 테스트

- 현재 학교명과 회계연도 보존
- 여러 예산항목 깊은 복사
- 기존 초안 덮어쓰기 취소와 승인
- 예시 원본 불변
- 확인 필요 경고 표시와 선택적 해제
- 구버전 저장자료 복원

### 회귀·배포 테스트

- 기존 직접 작성, 저장·복원, 초기화, 자동점검, 기안문 생성과 다운로드
- 전체 Vitest 테스트와 Vite 빌드
- PC 화면과 좁은 화면의 레이아웃
- 브라우저 콘솔 오류 없음
- 실제 16종 데이터로 Preview 검증

## 11. 구현 순서

1. 기존 초안 정규화의 회계연도와 재원구분 타입 문제 수정
2. 3개 분류와 16종 예시 데이터 작성
3. 예시 데이터 계산·개인정보 검증
4. 초보자용 재원 질문 화면
5. 세부 예시 목록·검색·상세 미리보기
6. `이 예시로 작성하기`와 덮어쓰기 보호
7. 확인 필요 자동점검
8. 전체 회귀테스트와 Preview 검증

## 12. 배포 원칙

- 모든 기능은 실제 16종 정적 데이터로 작동해야 하며 화면 모양만 있는 시제품으로 만들지 않는다.
- 테스트와 빌드가 통과한 뒤 Preview에만 배포한다.
- 사용자가 실제 흐름을 확인하고 최종 승인하기 전에는 Production 배포, Promote to Production, 운영 도메인 변경을 하지 않는다.
