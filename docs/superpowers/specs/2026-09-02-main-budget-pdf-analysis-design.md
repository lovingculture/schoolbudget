# 본예산 PDF·Excel 자동 계산 기능 교체 설계

## 목표

현재 `본예산` 메뉴의 부서별 세출 요구자료 통합·검토 기능을 제거하고, K-에듀파인에서 출력한 학교회계 세입·세출 본예산서 PDF 또는 Excel 파일을 분석하여 세입 기준금액과 일반업무추진비 편성 비율을 자동 계산하는 기능으로 완전히 교체한다.

새 기능은 정적 사이트의 브라우저 안에서만 파일을 분석한다. PDF·Excel 원본은 서버로 전송하거나 저장하지 않는다.

## 확인한 표본

### PDF

기준 파일 `2026 본예산(초등)(이름없음).pdf`는 OZ Report Viewer에서 생성된 A4 22쪽 PDF이다. 문자 레이어가 있으므로 PDF.js로 텍스트와 좌표를 직접 추출할 수 있다.

- 2쪽: `세입 세출 예산 총괄`, 세입예산총액 1,010,749천원
- 3~6쪽: `세입예산명세서`, 목적사업비전입금·수익자부담수입 및 세입 검증 항목
- 7~22쪽: `세출예산명세서`, 세부사업·세부항목·원가통계비목 계층과 예산액
- 금액 표시 단위: 예산액은 천원, 산출기초는 원

추가 PDF 4개를 확인한 결과, 2개는 문자 레이어가 있고 2개는 이미지로만 구성되어 있다. 학교급과 출력 형식에 따라 제목·구역명이 조금씩 다르므로 단일 문구나 고정 페이지 번호에 의존하지 않는다. 이미지형 PDF는 브라우저 OCR 대체 경로를 사용한다.

### Excel

`2026예산서.xls`와 `2026예산서1.xlsx`는 각각 `A2:AT764`, `A1:AR764` 범위의 단일 `표지` 시트이며, 두 파일 모두 병합 셀 5,530개를 포함한 인쇄용 서식이다. 별도의 세입·세출 시트를 가정하지 않고, 하나의 긴 시트에서 구역 제목과 계층 항목을 찾아야 한다.

- `.xls`와 `.xlsx`의 시작 행은 한 줄 차이가 난다.
- `.xls`는 금액이 숫자로, `.xlsx`는 쉼표가 포함된 문자열로 읽힐 수 있으므로 동일한 숫자 정규화를 적용한다.
- 두 파일 모두 세입합계 1,010,749천원, 목적사업비전입금 0천원, 수익자부담수입 207,176천원이다.
- 두 파일 모두 현재 예산액이 양수인 `일반업무추진비` 18건의 합계가 23,020천원이다.

기준 파일의 기대 결과는 8개 세입 확인 항목 합계를 기준으로 세입 기준금액 807,573천원, 일반업무추진비 23,020천원, 비율 2.85%이다.

## 선택한 접근

1. PDF와 Excel을 각각 파일 형식에 맞는 입력 어댑터로 읽는다.
2. 문자 PDF는 PDF.js로 문자와 좌표를 추출한다.
3. 이미지형 PDF는 페이지를 이미지로 렌더링하고 Tesseract.js 기반 브라우저 OCR을 지연 로딩하여 처리한다. OCR은 서버 전송 없이 브라우저에서 수행한다.
4. `.xls`와 `.xlsx`는 SheetJS `xlsx`로 워크북, 셀 값, 병합 범위를 읽는다.
5. 세 입력 경로를 공통 논리 행 모델로 정규화한 뒤 동일한 예산 분석기와 계산 규칙을 사용한다.

PDF 전체 문자열에 단순 정규식만 적용하거나 Excel의 고정 행 번호를 참조하는 방식은 페이지 줄바꿈, 병합 셀, 학교급별 형식 차이와 행 오프셋에 취약하므로 사용하지 않는다.

## 사용자 흐름

1. 본예산 메뉴에 진입하면 `본예산 PDF·Excel 자동 계산`과 파일 선택 영역만 보인다. 예시 값은 미리 채우지 않는다.
2. 사용자는 PDF, XLS 또는 XLSX 파일 하나를 클릭하거나 드래그하여 선택한다.
3. 파일 형식을 감지하고 파일명, 페이지 수 또는 시트 수, 예산구분, 학교명을 확인한 뒤 분석한다.
4. 문자형 PDF와 Excel은 바로 분석하고, 이미지형 PDF는 OCR 전환 안내와 페이지별 진행률·취소 기능을 제공한다.
5. 완료 후 요약 카드, 세입 검증표, 일반업무추진비 세부표, 분석 경고를 보여준다.
6. `다른 파일 분석`으로 현재 결과를 초기화하고 다시 시작할 수 있다.

## 계산 규칙

### 세입 기준금액

`세입 기준금액 = 학교운영비전입금 + 사용료 + 수수료 + 자산매각대 + 지난년도수입 + 이자수입 + 기타행정활동수입 + 순세계잉여금`

`세입예산총액 - (목적사업비전입금 + 수익자부담수입)`은 원본 세입합계 대조값으로만 사용한다. 두 값이 다르면 기준금액은 8개 항목 합계를 유지하고 원본 확인 경고를 표시한다.

다음 원가통계비목을 각각 추출하여 독립적으로 합산한다.

- 학교운영비전입금
- 사용료
- 수수료
- 자산매각대
- 지난년도수입
- 이자수입
- 기타행정활동수입
- 순세계잉여금

두 방식의 결과가 같으면 `일치`, 다르면 차이와 확인할 항목을 경고로 표시한다. 문서에 항목이 실제로 없는 경우는 0으로 처리하되, 페이지·시트 인식 실패나 낮은 OCR 신뢰도로 읽지 못한 경우와 구분한다.

`학부모부담수입`은 상위 집계 항목 확인용으로 함께 표시할 수 있지만, 기준금액 차감에는 하위 항목인 `수익자부담수입`을 사용하여 중복 차감하지 않는다.

### 일반업무추진비

세출예산명세서에서 원가통계비목이 정확히 `일반업무추진비`인 행의 현재 예산액만 합산한다. `목적사업업무추진비`는 제외한다. 각 행에 정책사업, 단위사업, 세부사업, 세부항목, 예산액을 연결하여 세부표를 구성한다.

`비율 = 일반업무추진비 합계 / 세입 기준금액 * 100`

비율은 소수점 둘째 자리까지 보여주되, 원본 계산에는 반올림하지 않은 값을 사용한다.

## 구조

### 입력 추출 계층

- `extractPdfPages.ts`: PDF.js로 페이지별 문자, x/y 좌표, 크기를 추출하고 문자 밀도로 이미지형 페이지를 판별한다.
- `ocrPdfPages.ts`: 이미지형 페이지를 적절한 해상도로 렌더링하고 Tesseract.js 한국어·영어·숫자 OCR을 수행한다. 워커와 언어 자료는 OCR이 필요할 때만 지연 로딩하며 진행률과 취소 신호를 반환한다.
- `normalizePdfLines.ts`: 직접 추출 또는 OCR 결과를 가까운 y 좌표 기준으로 한 줄로 묶고 x 좌표 순으로 정렬한다.
- `extractWorkbookRows.ts`: SheetJS로 `.xls`·`.xlsx`의 시트, 셀, 병합 범위를 읽고 숫자·쉼표 문자열·빈 병합 셀을 정규화한다.
- `normalizeBudgetRows.ts`: PDF 행과 Excel 행을 공통 `BudgetLogicalRow` 모델로 변환한다.

PDF는 먼저 저해상도 또는 문자 밀도 검사로 관련 구역과 이미지형 여부를 판별하고, OCR이 필요한 페이지만 분석용 해상도로 처리하여 불필요한 대기 시간을 줄인다.

### 예산 분석 계층

- `parseBudgetSummary.ts`: 총괄 구역에서 학교명, 회계연도, 예산구분, 세입예산총액을 읽는다.
- `parseRevenueStatement.ts`: 세입예산명세서 구역의 목·원가통계비목과 현재 예산액을 읽는다.
- `parseExpenditureStatement.ts`: 세출예산명세서 구역의 계층을 페이지·시트 행 사이에서 유지하며 일반업무추진비 행을 수집한다.
- `analyzeMainBudget.ts`: 파서 결과를 합치고 합계·비율·검증 상태·경고를 계산한다.

행 번호나 열 번호를 파일 전체에 고정하지 않는다. 각 구역의 제목과 열 머리글을 먼저 찾고, 그 구역 안에서 `예산액`, `본예산액` 등 현재 예산 열을 판별한다. 계층 항목의 숫자 접두어(`1.`, `2.` 등)는 제거한 뒤 정확한 항목명으로 비교한다.

추출과 분석을 분리하여, 공통 분석기 테스트는 PDF·OCR·Excel 라이브러리에 의존하지 않는 논리 행 픽스처로 검증한다.

### 화면 계층

- `MainBudgetPage.tsx`: 업로드, 분석 상태, 결과, 초기화를 조정한다.
- `MainBudgetUpload.tsx`: PDF·XLS·XLSX 클릭 및 드래그·드롭, 파일 형식·크기 검증을 담당한다.
- `MainBudgetProgress.tsx`: PDF 페이지 또는 Excel 시트 분석 단계, OCR 진행률, 취소 버튼을 표시한다.
- `MainBudgetSummary.tsx`: 세입 기준금액, 일반업무추진비 합계, 비율, 검증 상태를 표시한다.
- `RevenueBreakdownTable.tsx`, `GeneralBusinessExpenseTable.tsx`: 세부 결과를 반응형 표로 보여준다.

## 저장과 개인정보

- PDF·Excel 파일 자체와 OCR 원본 이미지는 저장하지 않는다.
- 분석 결과, 파일명, 파일 형식만 브라우저 `localStorage`에 저장하여 브라우저를 닫았다가 다시 열어도 결과를 복원한다.
- 새 저장 키 `school-budget:main-budget:file-analysis:v1`를 사용한다.
- 기존 세출 통합 저장 키 `school-budget:main-budget:expenditures:v1`와 설계 중 사용한 PDF 전용 키는 새 페이지에 처음 진입할 때 제거한다.
- `다른 파일 분석`을 누르면 새 분석 결과도 제거한다.

## 오류 및 경고

- PDF, XLS, XLSX가 아니거나 암호화·손상된 파일이면 지원 형식 안내를 보여준다.
- 워크북에 시트가 없거나 예산 구역을 찾지 못하면 파일명과 실패 구역을 표시한다.
- PDF 문자 추출량이 부족하면 자동으로 OCR로 전환한다. OCR 워커 또는 언어 자료 로드 실패 시 다시 시도와 파일 변경 선택지를 제공한다.
- OCR 신뢰도가 낮은 필수 항목은 0으로 확정하지 않고 `확인 필요`로 표시하며 인식 문자열과 위치를 함께 보여준다.
- `본예산`, 세입 구역, 세출 구역을 확인하지 못하면 분석을 완료하지 않는다. 제목의 띄어쓰기·학교급별 표현 차이는 허용한다.
- 필수 금액을 읽지 못하면 0으로 대체하지 않고 `확인 필요`로 표시한다.
- 합계 불일치는 읽은 값을 숨기지 않고 두 계산과 차이를 모두 보여준다.
- 0으로 나누는 비율은 계산하지 않는다.

## 화면 및 반응형 규칙

- 기존 포털의 청록·진청 색상과 타이포그래피를 유지한다.
- 데스크톱에서는 요약 3개를 한 줄에, 모바일에서는 세로로 배치한다.
- 세부표는 데스크톱에서 한 화면에 들어오도록 간격과 글자 크기를 조정하며, 작은 화면에서는 필요한 경우에만 가로 스크롤을 허용한다.
- 금액은 천원 단위와 원 환산을 함께 제공한다.
- OCR처럼 시간이 걸리는 작업은 현재 단계, 처리 페이지 수, 취소 가능 여부를 명확히 표시한다.

## 제거·변경 범위

- 기존 세출 Excel 업로드, 오류 검토, 요약, Excel 내려받기 전용 컴포넌트와 파서를 제거한다.
- 본예산 메뉴, 라우팅 키 `budget`, 홈 카드는 유지한다.
- 홈 카드와 이용안내의 본예산 설명을 PDF·Excel 자동 계산 기능에 맞게 바꾼다.
- 서버, 로그인, 결과 파일 내려받기는 이번 범위에 포함하지 않는다.

## 테스트

- PDF 문자를 줄로 묶는 좌표 정규화 테스트
- 문자 없는 PDF 감지와 OCR 전환·진행·취소 테스트
- OCR 결과의 숫자 쉼표, 음수, 항목명 오인식 보정 테스트
- `.xls`와 `.xlsx`의 단일 대형 시트, 병합 셀, 한 줄 행 오프셋, 숫자·문자 금액 정규화 테스트
- 세입예산총액·목적사업비전입금·수익자부담수입 추출 테스트
- 8개 세입 검증 항목 합산과 일치/불일치 테스트
- `일반업무추진비`만 수집하고 `목적사업업무추진비`를 제외하는 테스트
- 세부사업·세부항목이 페이지와 시트 행 사이에서 유지되는 테스트
- 기준 PDF·XLS·XLSX 결과: 807,573천원, 23,020천원, 2.85%
- 손상 파일, 필수금액 누락, 낮은 OCR 신뢰도, 0 분모 테스트
- 업로드·분석·결과·초기화·임시저장 화면 테스트
- 제공된 모든 PDF와 Excel 표본을 이용한 로컬 통합 검증
- 기존 본예산 세출 통합 화면과 안내 문구가 더 이상 노출되지 않는 회귀 테스트

## 완료 기준

1. 기준 PDF, XLS, XLSX를 브라우저에서 분석하면 각각 807,573천원, 23,020천원, 2.85%가 표시된다.
2. 문자형 PDF와 이미지형 PDF가 각각 직접 추출과 OCR 경로로 분석된다.
